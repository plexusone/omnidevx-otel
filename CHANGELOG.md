## [v0.1.0] - 2026-07-18

### Highlights

- Local telemetry plane: one loopback daemon for OTLP ingest, a read-only query API over the OmniDevX event store, and provisioned Grafana dashboards
- Durable live token/cost capture from Claude Code and Codex CLI, independent of local session-history retention
- Stdlib-only OTLP/JSON support — no protobuf or gRPC dependencies; log payloads acknowledged and discarded, never stored

### Added

- Daemon (cmd/omnidevx-otel): loopback OTLP/HTTP JSON endpoint composing omnidevx-core's genericotel receiver, with -addr/-person/-store flags ([`fcdbe87`](https://github.com/plexusone/omnidevx-otel/commit/fcdbe87))
- GET /api/series: on-demand time-bucketed aggregations (tokens, cost, activity, commits with AI share) over the canonical store, day or week buckets, since/until bounds, optional collection-mode filter ([`fcdbe87`](https://github.com/plexusone/omnidevx-otel/commit/fcdbe87))
- GET /api/health ([`fcdbe87`](https://github.com/plexusone/omnidevx-otel/commit/fcdbe87))
- Grafana provisioning: Infinity datasource against the query API and a four-panel dashboard (tokens/day, cost/day, session activity, weekly AI-assisted commit share) using Grafana time-range macros ([`8d62b4f`](https://github.com/plexusone/omnidevx-otel/commit/8d62b4f))

### Documentation

- PRD, TRD, PLAN, and ROADMAP specs (docs/specs): the store stays canon, the daemon owns no data, loopback only ([`c615476`](https://github.com/plexusone/omnidevx-otel/commit/c615476))
